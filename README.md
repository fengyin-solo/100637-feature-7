# 城市地下综合管廊运行维护管理平台

面向管廊主体台账、入廊管线登记、廊内环境监测、通风排水消防、结构沉降与渗漏处置、巡检检修与隐患整改、入廊作业审批和运维值班的一体化城市地下综合管廊运行维护管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `urban-utility-tunnel:entries` 这一项，或调用 `resetModule(模块)`。

## 入廊管线台账与结算口径（本次改动）

管线页只做「按条件收窄 + 状态联动」，业务判断集中在 `src/api/pipeline-service.ts`，
计费规则集中在 `src/data/billing.ts`，迁移集中在 `src/data/migrate.ts`。

1. **条件过滤**：权属单位、所属舱室、管线类型三个下拉精确匹配，过滤只收窄、不重排，
   台账保持按入廊日期落位的原次序。
2. **迁出收起**：已迁出管线默认不在在用结果里，页脚显示「另有已迁出 N 条已收起」；
   勾选「含已迁出」可单独捞出。页脚总条数、统计卡、状态图例都与当前表格同源。
3. **分页与停留**：每页 8 条；筛选条件、当前页、停留的管线（高亮行）持久化在
   `urban-utility-tunnel:view-state`，离开页面、刷新、重新打开都回到原来那条所在页。
4. **登记去重**：同一管线编号只认第一次落库，之后整笔按重复退回（不产生第二条、不覆盖首版）。
5. **存量回填与分批迁移**（`migrate.ts`，老浏览器里的旧数据首次打开自动迁移到 schema v2）：
   - 重复登记按管线编号合并，只保留最早一版（先比入廊日期、再比原始 ID），被合并的旧 ID 与日期写进保留行备注；
   - 早年缺入廊日期的管线，并入最早一批 `2023-03`，按管线编号升序顺延到该月末（03-30、03-31……），
     备注注明「纸质台账未登记，出处：《2023-03 入廊移交清册》同批管线」；
   - 每条管线写入 `迁移批次`（入廊日期所在月份），备注标注「上线前台账迁移：YYYY-MM 批次」；
   - 迁移后管线按入廊日期升序重新编号，结算单随之一并重算。
6. **结算联动**：一条管线一张结算单（`fees` 模块，导航「入廊费用结算」）。入廊费一次性计收，
   服务费按在廊月份累计（含入廊当月、迁出当月起停计）。管线页「办理迁出」后：
   管线默认从在用收起、结算单立即变「已停计」并写明迁出日期、值班清单同步一条迁出事项。
7. **新旧口径（切换日 `2026-10-01`，常量 `CUTOVER_DATE`）**：切换日前已迁出且已结清的两笔旧账
   （PIPE-2023-005、PIPE-2024-003）按旧台账金额誊抄，结算单标「原有结论」，不重算、不改写；
   切换日起的新登记、新月服务费、迁出停计按收费标准走「新口径」。新口径标准：
   给水 12000/800、燃气 15000/900、电力 18000/1100、通信 8000/500、热力 16000/1000、雨水 14000/850
   （入廊费元 / 月服务费元）。
8. **上报问题与值班同步**：管线页「上报问题」落到「运维值班交接」页的遗留问题清单，
   两处条数取同一份 `notices` 数据；登记、迁出也会同步到值班清单台账同步区。值班侧可关闭事项。
9. **老数据兼容决策**：旧版本 localStorage（无版本号）首次打开走 `upgradeDataset` 自动迁移，
   只动管线台账并重算结算单，其他 17 个模块原样保留；迁移是幂等的（已有迁移批次的行不会二次迁移）。
   想演示迁移过程可清掉 `urban-utility-tunnel:entries` 后重开页面；管线页「重置为初始台账」
   直接回到迁移完成后的初始状态。
